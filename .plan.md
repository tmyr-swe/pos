## 1. Goal

A single-terminal desktop POS for Chegg with:

- Swing desktop UI, Spring Framework (core, **not** Spring Boot), SQLite.
- Currency **KES** (`KSh 1,250.00`), integer-cent arithmetic.
- **No VAT** (tax engine present but disabled), cash + card, cash rounding to nearest 1 KES.
- A4/A5 PDF receipts and Z-reports.
- Four role-specific workspaces ("four apps in one"): System Admin, Store Admin, Cashier, Customer Kiosk.
- Full audit trail, shift/open-close, Z-reports, inventory sync, returns/voids.
- Palette `#722F37` (wine) / `#EFDFBB` (cream), font JetBrains Mono, supplied `logo.jpg`.

Single terminal, single active workspace at a time. All four workspaces share one service layer, database, and design system.

---

## 2. Non-negotiable engineering rules

1. **Money is never a `double`.** All monetary values are `long` cents in the domain and SQLite; `BigDecimal` only at parse/format boundaries. `Double.parseDouble` is banned from the pricing path.
2. **One calculation engine.** `CartCalculator`, `TenderCalculator`, and `Money` are pure; no UI or JDBC code performs arithmetic.
3. **DB work never runs on the EDT.** Service calls run on a dedicated executor; results are marshalled back with `SwingUtilities.invokeLater`.
4. **One transaction per checkout.** Header, items, payments, stock, stock movements, audit, and counter increment commit or roll back together.
5. **Permissions are enforced in services**, not only by hiding UI.
6. **Audit is append-only.** Successful mutations audit in the same transaction; security failures use `REQUIRES_NEW`.
7. **Timestamps stored UTC (ISO-8601 text), displayed in Africa/Nairobi (EAT), 24-hour.**
8. **Versioned schema migrations** from day one; never destroy data to upgrade.

## 7. Money, tax, discounts, rounding

### Money

- `long cents`; `BigDecimal` only in `Money.parse/format`.
- `Money.parse` accepts `1250`, `1,250`, `KSh 1,250.50`, `KES 1250`; rejects >2 decimals.
- `Money.format` → `KSh 1,234.57` (locale `en-KE`, forced space, symbol from settings).

### Tax (present, disabled)

- Rate stored as **parts-per-million**: 16% = `160000`, 8.875% = `88750`.
- `tax = (cents * ppm + 500_000) / 1_000_000` (HALF_UP, non-negative).
- Settings: `tax.enabled=false`, `tax.defaultRatePpm=0`.
- If enabled later, per-line tax is summed so receipt lines reconcile to the total; tax-inclusive extraction uses `(gross * ppm + d/2) / d`, `d = 1_000_000 + ppm`.

### Discounts

- `DiscountType { NONE, PERCENT, FIXED }`; percent value in ppm, fixed in cents.
- Line discount: `min(round(gross × ppm), gross)` or `min(fixed, gross)`.
- Cart discount distributed pro-rata by line net with **largest remainder**, so allocations sum exactly.
- Unit price and quantity are never modified by a discount.
- Role discount caps: `roles.max_discount_ppm`.

### Pipeline (`CartCalculator`)

```
gross_i      = unitPrice × qty
lineDisc_i   = cap(percent|fixed, gross_i)
net_i        = gross_i − lineDisc_i
cartDisc     = cap(percent|fixed, Σnet_i)
alloc_i      = largestRemainder(cartDisc, net_i)
taxable_i    = net_i − alloc_i
tax_i        = applyRate(taxable_i, taxRate_i)
total_i      = taxable_i + tax_i
subtotal     = Σ net_i
discount     = Σ lineDisc_i + cartDisc
tax          = Σ tax_i
total        = Σ total_i
```

Invariants: `Σ total_i == total`, `Σ alloc_i == cartDisc`, all values `>= 0`.

### Cash rounding (KES)

Applied to the **cash portion only**, at tender time:

```
cashPortion   = total − Σ(card applied)
roundedCash   = roundHalfUp(cashPortion to nearest 100 cents)
roundingCents = roundedCash − cashPortion
payable       = total + roundingCents
change        = cashTendered − roundedCash
```

Persisted as `sales.rounding_cents`; printed as a separate receipt line when non-zero. Card-only sales are exact.

## 8. Cart state

- `CartService` is in-memory, EDT-confined, not transactional.
- `LinkedHashMap<Long, CartItem>` keyed by `productId`; repeated add increments quantity (no duplicate rows).
- Price/tax snapshot at first add; manual price override creates a distinct key (manager-only).
- Quantity `<= 0` removes the line; max 999; stock warning at add, **hard validation at checkout**.
- Every mutation performs a full recompute and publishes exactly one `CartChangedEvent` carrying an immutable `CartSnapshot`.
- `CartTableModel` subscribes, uses `fireTableRowsUpdated` / `fireTableRowsDeleted`, guards re-entrancy, preserves selection by product id, and returns focus to search.
- `CartService` is a **prototype/session-scoped** bean per active workspace; the kiosk uses its own instance.

## 9. Tender & change

```java
record Payment(PaymentMethod method, long appliedCents, long tenderedCents, String reference) {}
record TenderState(long totalDue, long applied, long tenderedCash, long change,
                   long rounding, boolean valid, String error) {}
```

Validation:

| Case | Result |
|---|---|
| Σ applied == payable, cash tendered ≥ cash applied | valid |
| Σ applied == payable, card tendered == applied | valid |
| cash tendered < cash applied | invalid, "Cash tendered is short by …" |
| Σ applied < payable | invalid, "Still due …" |
| Σ applied > payable | invalid, "Payments exceed total by …" |
| card tendered ≠ applied | invalid |

- Quick tender chips: Exact, 50, 100, 200, 500, 1,000 KES, next-50/next-100.
- Change breakdown denominations (KES): 1000, 500, 200, 100, 50, 20, 10, 5, 1.
- `SaleService.checkout` re-validates; UI gating is convenience only.

## 10. Checkout transaction

```java
@Transactional(rollbackFor = Exception.class)
public long checkout(CheckoutCommand cmd) {
    Authz.require(Permission.SALE_CREATE);
    validate(cmd);                         // non-empty, payments == payable, shift open
    decrementStockOrFail(cmd.lines());     // UPDATE ... WHERE quantity >= ?
    long saleId = insertSaleHeader(cmd);   // RETURN_GENERATED_KEYS
    insertSaleItems(saleId, cmd.lines());  // batch, line_no ordering
    insertPayments(saleId, cmd.payments());// batch
    recordStockMovements(saleId, cmd.lines());
    audit(Ctx.SALE_COMPLETED, saleId);
    return saleId;
}
```

Order and rules:

1. **Decrement stock first** with a guarded `UPDATE inventory SET quantity = quantity - ? WHERE product_id = ? AND quantity >= ?`; any zero update count → `InsufficientStockException` → rollback.
2. Deterministic order by `product_id` for multi-line updates.
3. Receipt number inside the transaction via atomic upsert:
   ```sql
   INSERT INTO daily_counters(day, last_seq) VALUES (?, 1)
   ON CONFLICT(day) DO UPDATE SET last_seq = last_seq + 1
   RETURNING last_seq;
   ```
   Format `CHG-YYYYMMDD-0001`.
4. SQLite cannot reliably return generated keys for batch inserts → items carry `line_no`; refunds reference `(sale_id, line_no)`.
5. `JdbcTemplate` translates `SQLException` → unchecked `DataAccessException`, so rollback is automatic; `rollbackFor = Exception.class` is still declared.
6. Method must be called through the Spring proxy (never self-invoked).
7. Kiosk completion additionally flips `kiosk_orders.status` and both links in the same transaction.
8. Post-commit only: `@TransactionalEventListener(phase = AFTER_COMMIT)` → clear cart, generate PDF, notify dashboards. Print failure never rolls back a sale.

Test proof: force a second-line stock failure → zero sales/items/payments/stock changes.

## 11. Shifts & Z-report

- One open shift per terminal (partial unique index).
- Login → if no open shift, **Open Till** dialog (opening cash) before the workspace unlocks.
- Sales require an open shift (`shift_id` on every sale).
- Close: optimistic `UPDATE ... WHERE id=? AND status='OPEN'`, counted cash, expected cash, variance.
- Expected cash = `opening_cash + cash_sales − cash_refunds` (no payouts in MVP).
- Z-report aggregates by `shift_id`: gross, discounts, net, tax, cash/card, rounding, refunds, void count, transaction count, average ticket.
- **Persist an immutable `z_reports` snapshot including rendered text**, so reprints never change after later voids.
- Z-report PDF reuses the receipt renderer.

## 12. Audit

- Append-only `audit_log`; no update/delete paths.
- Business mutations audit in the **same transaction** (rollback removes the audit row).
- Security events (`LOGIN_FAILED`, permission denied) use `REQUIRES_NEW`.
- Actions: `SHIFT_OPENED`, `SHIFT_CLOSED`, `SALE_COMPLETED`, `SALE_VOIDED`, `REFUND_ISSUED`, `DISCOUNT_OVERRIDE`, `PRODUCT_CHANGED`, `STOCK_ADJUSTED`, `USER_CREATED`, `USER_UPDATED`, `USER_DEACTIVATED`, `ROLE_UPDATED`, `SETTINGS_CHANGED`, `LOGIN_SUCCESS`, `LOGIN_FAILED`, `BACKUP_RUN`, `KIOSK_ORDER_PLACED`.
- Role changes record before/after diff in `details`.

## 16. Receipts & PDF

- PDFBox 3.x; embed bundled JetBrains Mono TTF; KSh via ASCII.

## 20. Packaging & deployment — two builds

Target: **Linux and Windows**, produced from the same codebase. Java code stays OS-neutral (no separators, no hardcoded paths); OS differences live behind `AppPaths`, `PrintService`, and `TerminalId`.

### Artifacts

| Build | Artifacts |
|---|---|
| Universal | `chegg-pos.jar` (shaded, runs on any Java 25+) — dev/testing fallback |
| Linux | `jpackage --type app-image` + `.deb` (and `.tar.gz` app image); optional AppImage |
| Windows | `jpackage --type app-image` + `.msi` (and portable `.zip`); optional `.exe` |

`jpackage` bundles a `jlink` runtime — no Java installation required on the till.

### Constraint: no cross-compilation

`jpackage` **cannot build a Windows installer from Linux** (or vice versa). The app image contains platform binaries (`jpackage` launcher, JRE). So:

1. Run the Linux build on Linux (this machine).
2. Run the Windows build on a Windows machine/VM, **or** a CI matrix (`windows-latest` + `ubuntu-latest`) that publishes both artifacts.

Maven profiles/scripts:

```
-Pdist-linux     scripts/package-linux.sh
-Pdist-windows   scripts/package-windows.ps1
-Pdist-portable  scripts/package-portable.sh   (just the fat jar)
```

Windows prerequisites: JDK 25 for the build, WiX Toolset 3 for `.msi`. Linux: `dpkg`/`fakeroot` for `.deb`.

### Platform abstraction

```java
public final class AppPaths {          // per-user writable dirs
    static Path home();                // XDG_DATA_HOME / LOCALAPPDATA, -Dpos.home override
    static Path db(), receipts(), backups(), logs();
}
public interface PrintService { void print(Path pdf); }   // PDFBox PrinterJob; Desktop fallback
```

- **Linux:** `~/.local/share/chegg-pos/`; printing via CUPS; `.desktop` launcher + icon.
- **Windows:** `%LOCALAPPDATA%\CheggPOS\`; printing via the Windows spooler; Start-menu shortcut + `.ico`.
- DB, receipts, backups and logs are never written under `Program Files` or the install directory.
- Paths are used only via `java.nio.file.Path`; no string concatenation with `/` or `\`.
- `System.getProperty("os.name")` guards only the few genuinely OS-specific operations.

### JRE / modules

`jlink` runtime built from `jdeps --print-module-deps` output (expected: `java.base`, `java.desktop`, `java.sql`, `java.logging`, `java.prefs`, `jdk.unsupported`). SQLite JDBC extracts its native library to a temp dir at runtime on both platforms.

### First-run behaviour (both platforms)

1. Resolve `AppPaths.home()`, create dirs.
2. Open/create SQLite DB, run migrations, seed if empty.
3. Show login; seeded accounts force a password change.
4. Backups start on the configured nightly schedule (default 02:00 local).

### Release checklist

- `mvn verify` green on both platforms.
- PDF generated and printed on Linux + Windows.
- App icon and logo render at 100% and 150% scaling.
- DB survives restart; backup file opens in a second instance.
- Acceptance scenario passes on both builds.
